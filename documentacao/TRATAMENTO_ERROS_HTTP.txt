QUESTÃO 4 — TRATAMENTO ROBUSTO DE ERROS NA API
Transparência Brasil — Integração local do Qwen com FastAPI

1. OBJETIVO E CONTEXTO

A integração de um modelo de linguagem ao sistema introduziu novas situações de falha: modelo indisponível, falta de memória de vídeo, geração demorada e tentativas simultâneas de processamento. Além disso, qualquer serviço HTTP precisa distinguir problemas nos dados fornecidos pelo usuário de defeitos internos do servidor. O tratamento foi desenvolvido para orientar quem utiliza o aplicativo e, ao mesmo tempo, facilitar a análise técnica dos incidentes.

A implementação aproveita os Response Models da etapa anterior. As rotas existentes de despesas e de dados oficiais continuam independentes da execução do Qwen, de modo que uma falha do assistente não deve interromper as demais consultas.

2. COMO OS ERROS SÃO TRATADOS

O módulo api/erros.py centraliza o formato das respostas de erro, implementando handlers para entradas inválidas, exceções HTTP, respostas fora do contrato e falhas internas. Os retornos incluem o campo erro com código, mensagem compreensível e identificador único da requisição, também apresentado no cabeçalho X-Request-ID. O campo detail continua disponível por compatibilidade com chamadas existentes.

Cenário                                      HTTP   Código
Entrada inválida ou texto além do limite     422    ENTRADA_INVALIDA
Outra geração ocupando a GPU                  429    MODELO_OCUPADO
Falha interna inesperada                     500    ERRO_INTERNO
Saída fora do contrato FastAPI                500    RESPOSTA_INVALIDA
Modelo ausente, falha CUDA ou falta de VRAM   503    MODELO_INDISPONIVEL
Prazo de geração excedido                     504    TEMPO_LIMITE
Rota inexistente                              404    NAO_ENCONTRADO

A rota /processar_texto declara essas respostas em sua documentação OpenAPI. O erro 429 mantém o cabeçalho Retry-After: 5, além de preservar o limite de uma geração simultânea para proteger a RTX 4060 com 8 GB de memória de vídeo. Não foi criada uma fila oculta nem um mecanismo de repetição automática que pudesse duplicar processamento.

3. VALIDAÇÃO ANTES DA INFERÊNCIA

O FastAPI e o Pydantic rejeitam textos sem conteúdo legível, tipos incorretos, operações não previstas, campos desconhecidos e limites de tokens fora da faixa permitida. Esses casos são identificados antes de ativar o modelo. O retorno 422 relaciona os campos problemáticos sem reproduzir o texto enviado integralmente.

As saídas também são verificadas. Um resultado vazio, sem valores obrigatórios ou com dados de tipos incorretos não é publicado como resposta HTTP 200. Falhas internas não expõem rastreamentos de execução ou segredos ao usuário; o diagnóstico técnico fica nos logs locais.

4. MEMÓRIA DE VÍDEO E TEMPO LIMITE

O serviço de inferência identifica mensagens de falta de memória CUDA durante o carregamento ou a geração e as converte em mensagens de indisponibilidade (503), incluindo orientação para liberar VRAM ou reduzir o texto. Quando ocorre falha durante a geração, o código procura liberar o cache de memória da GPU e libera a trava que controla as solicitações.

Foi definido um limite de geração de 180 segundos por padrão, configurável por TP4_LLM_MAX_SECONDS entre 30 e 240 segundos. A biblioteca Transformers aplica max_time para interromper cooperativamente a geração, e o serviço verifica o tempo transcorrido ao retornar. Se o limite for atingido, responde 504, sem aceitar um texto truncado como conclusão válida. O limite não significa interrupção forçada imediata de um kernel CUDA em andamento, nem abrange necessariamente todo o tempo inicial de carregamento do modelo. Essa diferença é documentada para não prometer um cancelamento que a biblioteca não garante.

O cliente HTTP do Streamlit mantém prazo de 300 segundos para respostas do assistente e identifica também erros de conexão e de comunicação. As consultas comuns permanecem com limite menor, evitando lentidão desnecessária nas páginas de dados.

5. MENSAGENS AO USUÁRIO

Antes, uma solicitação recusada pelo backend poderia aparecer na interface como uma mensagem técnica contendo “429 Client Error: Too Many Requests”. Agora, o cliente HTTP interpreta o código e o corpo retornado. A página Assistente IA apresenta, por exemplo, a orientação de aguardar quando o modelo estiver ocupado e a instrução de verificar o servidor quando houver indisponibilidade. Também mostra o identificador da requisição para facilitar a investigação. Se uma nova tentativa falhar, a tela não mantém o resultado anterior como se fosse o retorno da requisição malsucedida.

6. TESTES E EVIDÊNCIAS

A bateria automatizada verifica casos de sucesso, validação de entrada, indisponibilidade de modelo, ocupação da GPU, exceção interna, falta de VRAM e timeout. Também valida os identificadores, os cabeçalhos HTTP, o contrato OpenAPI e as mensagens interpretadas pelo cliente do Streamlit. Os cenários de falha do Qwen são simulados de forma controlada, pois não seria seguro esgotar de propósito a memória da GPU durante um teste.

Os testes automatizados demonstram o comportamento do software, mas não substituem a verificação de inferência real no computador com a RTX 4060. A navegação visual do Streamlit e a geração local deverão ser conferidas após aplicar a atualização.

Comandos no PowerShell, na pasta original do projeto:
  .\.venv\Scripts\python.exe -m pytest -q
  .\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8000 --workers 1
  .\.venv\Scripts\python.exe scripts/verificar_erros_http.py
  .\.venv\Scripts\python.exe -m streamlit run app.py

Em http://127.0.0.1:8000/docs é possível testar POST /processar_texto com texto vazio para observar o retorno 422 sem carregar o Qwen. Em http://localhost:8501, a página Assistente IA permite realizar o teste positivo, que deve gerar uma resposta válida com código 200.

7. NAVEGAÇÃO DO APLICATIVO

O menu do Streamlit foi reorganizado por meio de st.navigation e st.Page nesta ordem: App, Gastos públicos, Estatísticas, Dados oficiais, Conteúdo da Web, API FastAPI e Assistente IA. As páginas Arquivos e Preparação para IA foram retiradas da navegação pública, mas seus arquivos e funções de bastidores foram mantidos no repositório para preservar o trabalho anterior. O projeto não foi renomeado nem teve dados ou pesos de modelo removidos.

8. LIMITAÇÕES

A API foi projetada para operação local e não deve ser exposta à Internet sem autenticação, controle de acesso e mecanismos adicionais de proteção. O tratamento de erro não garante a correção factual da resposta do LLM. O sistema não faz fila de geração; em concorrência, informa erro 429. A geração tem interrupção cooperativa, não cancelamento preemptivo de processos CUDA. Os dados ilustrativos e os dados oficiais permanecem em bases distintas.
